# 2026-07-18 — Dispatch COMPLETE-only + Run cockpit UX fixes + run dates + run-params review + Grid Report proc

Branch `ars_v2`. Triggered by a review of alloc row HB48 / M_W_TRSR / `1112108374` / CRM in session `20260716_172414_619` whose `ALLOC_REMARKS` carried a confusing `OVERSHOOT`+`SCALE` double-stamp.

## 1. COMPLETE-mode overshoot fall-through bug (fixed)
- **Root cause:** in `rule_engine_per_opt.py` (`_run_band_per_opt`, RL/TBC `mbq_budget` path ~L1133) the SCALED round-then-shave block was an **unguarded fall-through** after `if mode == 'COMPLETE':`. A COMPLETE overshoot admit (`werks_cap ≥ 0.5×total_need`) stamps `MBQ_CAP_OVERSHOOT` and intends a FULL ship ("fall through"), but with no `continue`/guard it dropped into the scale block → rescaled to the cap → stamped `MBQ_CAP_SCALE`.
- **Effect:** contradictory double-stamp; OPT shipped the **scaled** qty not the full need. Repro: need=15, cap=10, shipped 10 (not 15).
- **Fix:** scale block is now `elif mode == 'SCALED':` — COMPLETE and SCALED are mutually exclusive. COMPLETE-overshoot now ships full need with a single `OVERSHOOT` stamp.
- See [[Rule Engine (per_opt)]], [[dispatch-complete-only]].

## 2. SCALED disabled end-to-end
- **Frontend** (`ListingPage.jsx`): SCALED radio still **visible** but greyed-out/non-selectable (user asked to keep it visible-but-disabled); stale saved settings normalize to COMPLETE on load.
- **Backend** (`listing.py`): `GenerateRequest._force_complete_dispatch` — a Pydantic `field_validator` coerces any `rl/tbc_dispatch_mode` (incl. direct-API `SCALED`) to `COMPLETE`.
- **Engine:** the `elif` guard keeps scale code dead-but-guarded.

## 3. Hold Control pre-fill driven by Run Pool
- Selecting the pool pre-sets the three "Skip hold" toggles so a selection is never missed: **FRESH ⇒ skip hold UPC + GM** (APP off); **GRT ⇒ all three**. Pre-fill, still editable. Initial page state matches default FRESH. (`ListingPage.jsx`)
- Reminder: checked "Skip hold — X" = that segment's TBL rows ship like RL/TBC (no warehouse hold); payload inverts to backend `apply_hold_seg_*`.

## 4. Run Setup MAJ_CAT search — exact SSN group now surfaces
- **Bug:** `SearchSelect` group matcher used substring `.includes()` + `.slice(0,6)` over groups in SEG→DIV→SUB_DIV→SSN order. A short query like `s` substring-matches many longer codes (`MENS`, `SSNL`, …) that precede SSN groups, so the exact **SSN: S** bulk-select row was cut off and never showed.
- **Fix:** rank matches exact → prefix → substring (shorter code wins ties), cap raised to 8. `maj_cat_attr_map` source (`ARS_MSA_GEN_ART` SEG/DIV/SUB_DIV/SSN, verified populated) was correct — bug was pure UI ranking.
- See [[Listing]].

## 5. Run dates (information-only): `STOCK_CONSIDER_DT` + `PICKING_DT`
- Two date fields added to the Run Setup cockpit (`ListingPage.jsx`), **both mandatory** (generate-guard blocks either empty): **Stock Consider Date** (defaults to **D-1 / yesterday**) and **Picking Date** (**blank by default** — no assumed date, user picks it consciously each run).
- `GenerateRequest` (`listing.py`): `stock_consider_dt: str` + `picking_dt: str`, both required, non-empty ISO `YYYY-MM-DD` (shared `_require_run_date` validator).
- **Part 8.36** in `/generate` `ALTER`s `ARS_ALLOC_WORKING` (adds both `DATE` cols if missing) + `UPDATE`s every row — mirrors the Part 8.35 ALLOC_TYPE stamp, runs BEFORE Part 8.4 parking.
- **Propagation is automatic:** `parked_history.py` copies columns by introspection (`_reconcile_parked_columns` → PARKED, `_reconcile_history_columns` → HISTORY), so both columns + values reach `ARS_ALLOC_PARKED` and `ARS_ALLOC_HISTORY` with no parking-code change.
- Also two `LISTING` rows in `ARS_RUN_PARAMS_AUDIT` + seeded in the data dictionary. **Never used in any stock/MSA/allocation math — pure traceability.**
- See [[Data Model]], [[Listing]], [[run-dates-metadata]].

## 6. Session-wise Run Parameters review (`ARS_RUN_PARAMS_AUDIT`)
- **Finding:** the storage the user wanted already existed — `ARS_RUN_PARAMS_AUDIT` stamps ~30 rows/run (tall/EAV, keyed `RUN_ID`+`SESSION_ID`+`USER_ID`+`RUN_TS`) covering every tunable across LISTING/RANKING/ALLOCATION/SEC_CAP/FLAGS. Two gaps: the sec-cap STANDARD vs MATRIX condition was buried in the `growth_matrix` JSON, and there was **no read/review surface**.
- **Backend:** added a flat `("SEC_CAP","sec_cap_mode", "MATRIX" if _gm_enabled else "STANDARD")` audit row (`listing.py`, guarded `_gm_enabled` in the matrix-load except). New read endpoint `GET /listing/sessions/{session_id}/run-params` — latest run of a session, grouped output + `conditions` summary; back-compat derives `sec_cap_mode` from `growth_matrix.enabled` for pre-today runs; never 500s.
- **Frontend:** standalone **Run Parameters** page (`RunParamsPage.jsx`, route `data-prep/listing/run-params`), opened via a **Run Parameters** button in the Listing cockpit next to *View Logs* (passes current session via `?session=`). Session-A picker (defaults to last run / preselect), a **Compare** toggle button that reveals a session-B picker with per-row diff highlighting, a conditions pill strip (sec_cap_mode, dispatch, cont_fallback, alloc_type…), and grouped tables. `runParams(sid)` added to `listingAPI`. (Initially built as a collapsible cockpit section; moved to its own page per user request.)
- **Pre-existing bug fixed — audit table was always empty.** The audit block created the table via `_run`/`run_sql` (which commits) but wrote rows via `ac.execute(...)` with **no commit**, so SQLAlchemy rolled the INSERT back on `with de.connect()` close. `ARS_RUN_PARAMS_AUDIT` had 0 rows since inception. Fix = `ac.commit()` after the executemany (`listing.py` ~L962). Verified: without commit 0 rows persist, with commit rows survive a fresh connection. Note: only runs AFTER this fix + a backend restart populate; historic sessions stay blank (rows were never persisted).
- No new table, no migration, no engine/allocation-math change — pure traceability + read UI. See [[Data Model]], [[Listing]].
- **Grid config + Trends (2026-07-18):** audit now snapshots `ARS_GRID_BUILDER` per run — a `GRIDS` group (one row per grid: status/group/capping/cap%/wt/opt_sale) + numeric `active_grid_count`/`capping_grid_count`/`cap_pct::<grid>` + `SEC_CAP/matrix_bands`. New `GET /run-params/catalog` + `/run-params/trend` endpoints and a **Trends** tab on the Run Parameters page (Compare | Trends): pick any params → numeric ones overlay as recharts lines, categorical (sec_cap_mode, alloc_type, dispatch, grid status) as step charts. `GRIDS` group also shows in Compare with diff highlighting. Verified live (3-series numeric chart + categorical step + GRIDS compare) via DOM; grid metrics populate on runs after this landed. Also fixed the audit-INSERT-never-committed bug earlier the same day (the reason the table had been empty).

## 7. Grid Report stored proc — `dbo.usp_ars_grid_report`
- Built an analytics report over the grid tables and wrapped it as a proc (`backend/sql/usp_ars_grid_report.sql`). Params `@GridTable` (default `ARS_GRID_MJ`), `@WERKS`, `@MAJ_CAT`. Works unchanged for every secondary grid (`_RNG_SEG` / `_MERGE_RNG_SEG` / `_M_YARN_02` / `_FAB` / `_CLR` / …) — `@DimCol` is auto-detected as the column the target has that `ARS_GRID_MJ` lacks.
- Grid columns expanded dynamically with **type-aware `ISNULL`** (numeric→0, text→''); store/product/listing/MSA/alloc/hold joined as selected columns. Adds `MSA_OP_Q`, `MSA_CL_Q` (MSA − alloc consumed), `OP_OPT_CNT_>50_PCS` + `CL_OPT_CNT_>50_PCS` (# of GEN_ART+CLR with `SUM(FNL_Q)>50` — OP from `ARS_MSA_TOTAL_HISTORY`, CL from live `ARS_MSA_TOTAL`), and store-level hold `OPEN_REM/CONSUMED_TODAY/ADDED_TODAY/CLOSE_REM` (opening = closing − added + consumed).
- **Dim-aware hold fix:** hold was inflating on secondary grids (MAJ_CAT-level hold repeated on every dim row). Fixed with a `pdim` CTE mapping `VAR_ART → dim` via `vw_master_product.ARTICLE_NUMBER` so `hold`/`hmov` group by `(WERKS,MAJ_CAT,dim)`. Verified HB05/M_JEANS RNG_SEG split (V41/P14/SP0/E0) sums to the MAJ_CAT total 55; base grid unchanged.
- **Data-quality finding:** MAJ_CAT `[A-Z]-` prefix (e.g. `B-M_TEES_HS`) exists in grid/MSA/listing but never in alloc/hold, and prefixed+unprefixed coexist as distinct grid rows → raw-MAJ_CAT joins silently drop ~0.4% of grid rows (left as-is, not normalized). See [[Known Risks and Doc Drift]].
- Live-validated on HOPC866: per-column match vs source for HB07/M_JEANS (24 cols) and hold identity for a mover; full base run 180,989 rows. See [[Reports]].
