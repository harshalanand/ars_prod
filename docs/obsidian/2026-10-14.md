## Get Data: Stop for a running sync run (ars_v4, for_merge, committed 0cae6fc, not deployed)
- **Gap:** Sync Jobs had only Enable/Disable. Disabling does not stop a live run.
- **Added:** `POST /api/v1/get-data/runs/{run_id}/stop` and a Stop action. The run's 3 s heartbeat poll makes it work across workers. It cancels Snowflake queries, kills bcp, and drops the stage only while the run holds the job lock. `hb.commit()` before swap/MERGE/INSERT is the point of no return. Spec: `frontend/public/docs/manual/get_data.md`. [[project_get_data_stop_run_2026_10_14]]
- **Gotcha:** an ALTER TABLE inside a rolled-back test moved the GD_RUN identity 171 -> 20171. Reseeded with DBCC CHECKIDENT. [[gotcha_identity_cache_jump_on_rollback]]

## Get Data: "When the source changes" trigger (ars_v4, for_merge, committed 895777f, NOT deployed)
- **What:** third Sync Jobs trigger `on_change`. A job runs once its Snowflake source tables have changed and gone quiet, with an optional daily safety run. Spec: `frontend/public/docs/manual/get_data.md`, section "When the source changes (trigger on_change)" and Recorded rules 2026-10-14. [[project_get_data_on_change_trigger_2026_10_14]]
- **Code:** new `backend/app/services/get_data_watch.py` (pure `decide()`, never imports the sync service). The scheduler orchestrates it each tick. A run captures the change token before its data query.
- **Schema:** 9 additive nullable GD_JOB columns were added for real on HOPC866 during testing. The running code ignores them. Test DML was rolled back, and identity counters were reseeded to 173/33.
- **Gotchas:** `SYSTEM$LAST_CHANGE_COMMIT_TIME` on a view misses nested tables, so base tables are watched. [[gotcha_snowflake_change_time_view_nesting]] The HOPC866 clock runs about 5 min ahead of the app server. [[gotcha_hopc866_clock_ahead_of_app_server]]
- **Next:** no real job is on on_change yet. Suggested first trial: ST_MJ_DAY_WISE_CONT, after a backend restart.
