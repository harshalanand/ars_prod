# 2026-08-13 — I_ROD eligibility (BR-16/FS-10), infrastructure corrections & Cap Ladder impact

## BR-16 / FS-10 — I_ROD-aware option eligibility (`OPT_REQ_ROD`) — IMPLEMENTED

Full detail → [[project_irod_eligibility]]. Dossier updated: `frontend/public/docs/manual/listing.md` (FSD + Recorded rules), `backend/app/docs/BRD_ARS_V2.md` (R05 row + param table), `ARS_DATA_DICTIONARY` seed.

### The gap

The demand gate tested a **single round** (`OPT_REQ_WH >= 1`) while `I_ROD` — the number of dispatch rounds an option is entitled to — was honoured **only inside the engine, at size grain** (`rule_engine_per_opt.py:835-841`). Options stocked above round 1 but below their full entitlement were rejected `NO_DEMAND` / `R05_REQ_POS` and the engine never evaluated them, even though it would have shipped them in round 2.

Canonical case (confirmed live on dev): `HS11 / 1241092810 / SKY_BLU`, `I_ROD=2`, `OPT_MBQ=9`, `STK_TTL=12` → `OPT_REQ_WH = MAX(0, 9−12) = 0` → rejected, despite a genuine 6-unit shortfall against the `2 × 9 = 18` entitlement and `MSA_FNL_Q = 1,248` sitting in the RDC.

### The formula (Part 4c, `ARS_LISTING`)

```
rod_target  = OPT_MBQ_WH + (I_ROD−1) × OPT_MBQ   if OPT_TYPE = 'TBL'
            = I_ROD × OPT_MBQ                    otherwise
OPT_REQ_ROD = MAX(0, ROUND(rod_target − STK_TTL, 0))       # I_ROD = 0 counts as 1
```

Three things that are **not** negotiable:

1. **TBL counts the hold buffer ONCE** — mirrors `rule_engine_per_opt.py:837`. A naive `I_ROD × OPT_MBQ_WH` multiplies `hold_days` by the round count. Verified on dev: `HM25` TBL `I_ROD=2 MBQ=20 MBQ_WH=28` → **48** correct, 56 inflated.
2. **`NULLIF(I_ROD,0) → 1`** — many R05-blocked rows carry `I_ROD = 0`; without this they evaluate to a negative entitlement.
3. **Clamp at 0 + `ROUND(…,0)`** — consistent with `OPT_REQ` / `OPT_REQ_WH`.

Placement is deliberate: immediately after the `OPT_REQ_WH` UPDATE, the earliest point where `OPT_MBQ`, `OPT_MBQ_WH`, `OPT_TYPE` (Part 3.6) and `I_ROD` (Part 3.5a) are all populated.

### Three gates switch together — and must agree

| Layer | Where | From | To |
|---|---|---|---|
| 1 | Part 6.6 `gate_demand` (`listing.py`) | `OPT_REQ_WH >= 1` | `OPT_REQ_ROD >= 1` |
| 2 | Stage A `R05_REQ_POS` (`rule_engine_new._stage_a_apply_rules`) | `OPT_REQ_WH < 1` | `OPT_REQ_ROD < 1` |
| 3 | `/create-final` extract filter | `OPT_REQ_WH >= :min_req` | `OPT_REQ_ROD >= :min_req` |

⚠ **If Layer 1 admits a row that Layer 2 rejects (or the reverse), Part 7 silently DROPS it** whenever `shift_all_to_working` is off — that shift filters `ELIG_FLAG = 1`. Shared helper `listing._irod_gate_on()` exists so every call site resolves the switch identically. Each layer falls back to `OPT_REQ_WH` when the column is absent, so pre-FS-10 snapshots stay readable.

**Reason codes unchanged** — `NO_DEMAND` and `R05_REQ_POS` keep their strings and CASE-ladder positions. Only the arithmetic tightens from *"needs nothing in round 1"* to *"needs nothing across all I_ROD rounds"*, so dashboards and saved queries keep working.

### `NO_REQ` label alignment — now unreachable by construction

`SZ_REQ` stays a 1-round figure. Without this fix, a newly admitted option shipping nothing because the **pool** is empty would be labelled `NO_REQ` (`SZ_REQ <= 0`) instead of the truthful `NO_POOL_MSA` — sending reviewers after demand when the problem is supply, because the classifier tests `SZ_REQ` before the pool. The `NO_REQ` branch in `rule_engine_pandas.py` + `rule_engine_new.py` now uses the same I_ROD target as the `ALREADY_STOCKED` branch directly above it: no I_ROD demand → `ALREADY_STOCKED`, anything else shipping zero → supply problem. Label-only; gated so a flag-off run stays byte-identical.

### Deliberately unchanged

- `OPT_REQ` / `OPT_REQ_WH` — feed excess arithmetic and `OPT_PRIORITY_RANK` ordering. Redefining them would silently reorder dispatch and rewrite every published report.
- `MJ_REQ` / `MJ_MBQ` / R09 headroom / `*_mj_req_cap_pct` / sec-caps — stay 1-round by decision. Newly admitted options compete inside **today's** MAJ_CAT budget rather than enlarging it. Measure first.
- `rule_engine_per_opt.py` — correct as-is. Band mask is `OPT_TYPE = ot AND I_ROD >= r AND ALLOC_STATUS NOT IN ('SKIPPED','INELIGIBLE')` with **no `SZ_REQ` filter**, and a size receiving nothing in round 1 only gets an audit remark — never `SKIPPED`. An admitted row is still live for round 2.
- `SZ_REQ` / `SZ_REQ_WH` values — only the `NO_REQ` label moved.

### Configuration — two dials, OR'd, both default OFF

| Switch | Where | Default |
|---|---|---|
| `RULE_R05_USE_IROD` | `rule_engine_new.py` flags block | `False` |
| `use_irod_eligibility` | `GenerateRequest` (per run) | `False` |

Per-run value is stamped into `ARS_RUN_PARAMS_AUDIT` + session `REQUEST_JSON`, and threaded to the engine **and** the `/retry-failed` path. With both at default the deployed code is behaviourally identical to pre-FS-10 — the column is computed and visible, but no gate reads it. Rollback = set either to `False` and re-run; `OPT_REQ_ROD` is additive and nullable, so no schema rollback. **No migration script** — `ARS_LISTING` is dropped and recreated every run, and parked/history self-reconcile via `_reconcile_history_columns()`.

### Propagation gotcha

`_FINAL_KEEP_COLS` needs `OPT_REQ_ROD` listed **explicitly** — the `_FINAL_KEEP_SUFFIX = {"_REQ"}` pattern does **not** match a name ending `_ROD`. Same trap in the SLOC auto-detector: `_ROD` isn't in `bad_suffixes`, so the column must also join the `non_sloc` set or it gets mistaken for stock. Both export column lists updated too.

## Shadow-grid model — overview

**Architecture:** Base grid owns everything; merge grids are system-owned read-only shadows.

**Key properties:**
- **Creation trigger:** User saves a merge rule → `_autocreate_merge_grid()` creates merge grid if missing
- **Inheritance:** Merge grid inherits `group` / `sec_cap_applicable` / `sec_cap_pct` from base UNLESS explicitly overridden (explicit config wins)
- **UI:** GET /grid-builder/hierarchy/schema marks merge columns `derived=1` (read-only); base columns `editable=1`
- **Upload safety:** file_upload_service DROPS merge columns, returns `ignored_derived_columns` + note, then re-runs `_populate_merge_columns()` so base and merge never drift
- **Deletion guard:** Deactivating base grid WARNS which Active merge grids it orphans; DELETING base is BLOCKED (400)
- **Coupling hazard:** ⚠ If merge grid (e.g., MJ_MERGE_RNG_SEG, the family lender) is deactivated/set `sec_cap_applicable=0`, the base loses its family and borrowing stalls silently

**Design rationale:** Separate ownership (system ≠ user) prevents drift and accidental corruption. Prefix+number naming (MERGE_col, MERGE2_col) makes parent recoverable.
