# 2026-10-10

## All-RDC variants of VAR_ART_ALC_RPT and PARK_TEMP (commit 123f2e6)
- **Defect:** both base procs group the MSA pool AND the consumption side by RDC, then join `a.RDC = b.RDC`. A store's consumption is charged to its own RDC, but cross-RDC supply is routine, so the netting hits the wrong pool and drives `EXTRA_MSA_QTY` negative. Base: 2,202 negative rows (USP_VAR_ART_ALC_RPT), 7,636 (USP_PARK_TEMP). ALLRDC variants: 0 in both.
- **Key insight:** at all-RDC grain, summed across every RDC, keying by RDC or by SRC_RDC gives the identical total. No SRC_RDC logic or OBJECT_ID fallback needed (unlike [[Reports]] ALLRDC MSA Master). PARK_TEMP's consumption source `ARS_LISTING_WORKING_HISTORY` has no SRC_RDC column at all, so all-RDC is the only correct option there.
- **PARK_TEMP changed:** MSA_QTY CTE (grouping, join, outer GROUP BY) drops RDC; ALLOC_AGG windows ALC_TTL / HOLD_TTL / FROM_HOLD_TTL partition by MAJ_CAT, GEN_ART_NUMBER, CLR. **Unchanged:** per-store ALLOC_Q_MACHINE and HOLD_QTY (keyed on WERKS), and the MAJ_CAT / MERGE_RNG_SEG / RNG_SEG / MVGR-1 / FIT groups. RDC stays as a descriptive output column.
- **VAR_ART_ALC_RPT changed:** `cte_msa_stk` drops RDC; join is `MAJ_CAT` + `VAR_ART = ARTICLE_NUMBER`.
- **Validation:** USP_VAR_ART_ALC_RPT 36,925 rows / 36 cols, 7.5s base vs 7.1s ALLRDC. USP_PARK_TEMP 313,283 rows / 101 cols, 66.2s base vs 69.0s ALLRDC.
- **Expected effect:** SUM(OP_MSA_QTY) roughly doubles (2.82M to 5.15M; 21.25M to 41.21M) because each row now sees the national pool. Not a bug, but anyone comparing totals must know it.
- **Deploy check:** OBJECT_DEFINITION vs disk file, after stripping comments and folding whitespace from the CREATE/ALTER PROC token. All 8 ARS report procs identical disk vs live on HOPC866 and ARSDBPRO. Gotcha: a naive hash that keeps the trailing `GO` reports false DIFFERS, because `GO` is a client batch separator and never part of the stored definition.
